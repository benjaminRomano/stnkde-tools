Reconstructing the paper figures

The reference images were extracted from the supplied paper. The reconstructed before and after now use matching display coverage, framing and color scales. Click either image for a full-screen, zoomable view; download the large PNG or vector SVG for closer inspection. The original reference is available beneath each pair. The paper and reconstruction differ for three reasons: estimated zoom/camera, current road geometry and updated crash records, and unavailable original class breaks and planar-KDE settings. Zoom explains part of the mismatch; it cannot explain all of it. Before/after comparisons within this reconstruction use the same inputs and framing. Methods and provenance

What changed

  1. Pass network distance into the spatial kernel.
  2. Smooth neighboring times on the source lixel too.
  3. Separate the computed density field from the choice of which cells to display.
  4. Use explicit calendar coordinates and complete 24-hour cycles.
  5. Find the exact nearest geometry; flag matches beyond 100 m.
  6. Build and split the graph deterministically, with atomic database phases.

The calculation fixes retain the repository’s Epanechnikov kernel. The paper calls this quartic; the separate quartic option implements the stated biweight kernel and is a modeling change.

The dataset contains every year and hour, so missing-bin handling does not produce extra differences here. At annual bandwidth one, adjacent years have zero kernel weight, so the source-time fix changes the hourly calculation. The 100 m assignment limit is an explicit data-quality policy, separate from exact-nearest matching.

Smoothing and faint coverage

Both kernels have compact support: contribution is zero at and beyond 100 m. Quartic has a faster falloff near the boundary than Epanechnikov. Full-field maps show more roads because smoothing reaches zero-count cells. Displaying only event-bearing cells was an intentional sparse-output choice in the original project; it is not itself an arithmetic error. A display cutoff hides faint colors without changing the estimator, counts or reported statistics; gray roads still show geographic context. Use 0% to show every positive value. Reducing the spatial bandwidth would instead change the estimated footprint and requires recomputation.

Efficient, checked computation

Indexed PostGIS matching, bounded shortest paths on a sparse midpoint graph, and matrix-based density aggregation replace repeated queries and Python neighbor loops. pgRouting independently checks sampled distances, and the unmodified repository worker checks the reconstructed baseline arithmetic.
